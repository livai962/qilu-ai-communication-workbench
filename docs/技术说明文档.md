# 技术说明文档 · 齐鲁智传 · 山东本土文化 AI 传播智能工作台

## 0. 系统概览

工具采用三层架构，完整覆盖「输入 — 处理 — 输出」业务闭环，并内置全链路留痕能力。

```
┌─────────────────────────────────────────────────────────┐
│ 表示层（Streamlit）                                        │
│ 结构化输入面板 ｜ 文案编辑 ｜ 分镜配图 ｜ 合规与留痕工作台  │
├─────────────────────────────────────────────────────────┤
│ 业务逻辑与提示词层（core/）                                 │
│ 知识库 ｜ 提示词模板与版本 ｜ 生成工作流 ｜ 合规引擎        │
│ 受众分析 ｜ Diff 比对 ｜ 导出与溯源                         │
├─────────────────────────────────────────────────────────┤
│ 服务与存储层                                               │
│ 在线大模型接口（OpenAI 兼容） / 本地离线兜底引擎           │
│ JSON 持久化：原始输入 · AI 全版本 · 人工修改轨迹           │
└─────────────────────────────────────────────────────────┘
```

技术栈：Python 3.12、Streamlit 1.67、pandas、python-docx、diff-match-patch、requests。

## 1. API 调用逻辑与提示词工程策略

### 1.1 模型接入与调用逻辑

- **接口形态**：采用 OpenAI 兼容的 `/chat/completions` 接口，可对接豆包、通义千问、商汤等提供兼容协议的模型，或主办方技术支持接口。
- **配置注入**：`LLM_ENABLED / LLM_BASE_URL / LLM_MODEL / LLM_API_KEY / LLM_TIMEOUT` 全部来自环境变量或本地 `.env`；`core/config.py` 提供脱敏后的配置概览，界面与日志不回显密钥。
- **请求结构**：
  - `system`：角色分工、本土文化要求、合规红线、输出 JSON 契约；
  - `user`：由结构化输入组装，内嵌各平台内容结构、语气、篇幅与标签要求；
  - `temperature=0.7`，`response_format=json_object`。
- **容错与降级**：超时、HTTP 错误、返回解析失败或字段缺失时，捕获异常并自动切换本地离线兜底引擎；降级原因写入 `engine_note`，界面可见，保证评审现场不因网络或密钥问题中断。
- **输出契约统一**：在线引擎与本地引擎返回同一字段结构（见 1.4），下游校验、编辑、留痕、导出逻辑无需区分来源。

### 1.2 提示词工程策略

1. **角色与边界前置**：系统提示词明确“AI 出初稿、人工定终稿”的分工，禁止输出可直接定稿的承诺。
2. **领域知识注入**：营销专业逻辑 + 齐鲁文化属性 + 合规红线写入系统提示词；平台结构、受众画像、文化元素由外置知识库按场景检索后注入用户提示词，不在代码中堆砌一次性指令。
3. **结构化输出契约**：要求模型严格输出固定 JSON，降低后处理歧义；缺失字段由 `_normalize` 用本地模板补齐。
4. **模板可配置、可追溯**：提示词集中在 `core/prompts.py`，带版本号 `PROMPT_VERSION`；每次生成的提示词包（系统词、用户词、版本、迭代记录）随会话留痕，界面可展开查看。
5. **合规约束内化**：提示词层面先规避极限词、功效承诺、站外导流；合规引擎再做二次机器校验，形成“提示词预防 + 规则校验”双保险。

### 1.3 本地离线兜底引擎

未配置模型时，由规则模板引擎完成同等产出：按场景选择文化元素、按平台套用结构模板、按风格系数切换语气词库，生成标题、正文、分平台文案、标签、5 镜分镜与配图提示词。该引擎同时作为线上模型异常时的 Plan B。

### 1.4 输出数据契约

```json
{
  "headline": "主标题",
  "body": "主推正文",
  "platform_copy": { "小红书": "...", "抖音": "...", "公众号": "..." },
  "tags": ["话题标签"],
  "selling_points": ["提炼卖点"],
  "storyboard": [
    {"shot": 1, "visual": "画面", "voiceover": "口播", "duration": "时长",
     "subtitle": "字幕", "image_prompt": "配图提示词"}
  ],
  "image_prompts": ["AI 配图提示词"],
  "audience_notes": "受众沟通要点"
}
```

## 2. 本土场景向功能模块转化的设计思路

### 2.1 场景垂直化，拒绝通用套壳

输入层用下拉与表单锁定三类山东本土场景，而非开放聊天框：

| 场景 | 知识库调用 | 典型产出侧重 |
| --- | --- | --- |
| 齐鲁非遗 / 老字号焕新 | 非遗品类、老字号、鲁菜元素 | 年轻化表达、工艺故事、体验项目 |
| 县域文旅打卡 | 文化主题、地标、受众画像 | 出片路线、打卡场景、行程引导 |
| 助农农产品 | 文化主题、地方饮食元素 | 产地与品质表达、团购 / 直播预热 |

### 2.2 平台结构内置

`culture_elements.json` 为小红书、抖音、公众号分别配置内容结构、语气、篇幅与标签风格；生成工作流按所选平台套用对应模板，保证“一次录入、分平台适配”。

### 2.3 文化元素匹配

- 文旅场景优先文化主题，再补地标；农产品优先文化主题，再补地方饮食；
- 本地引擎会优先选择与项目名称存在词面重合的文化元素（如“曲阜三孔”匹配“三孔”），减少地标错配；
- 在线引擎同样在用户提示词中获得候选文化元素清单作为参考。

### 2.4 合规知识外置

`sensitive_words.json` 按类别维护词库、风险等级、法规依据与修改建议；词库可后台扩充，不写死在代码中。对“国家级非遗 / 国家级传承人”等官方称谓做语境排除，避免误判。

## 3. 人机协作流程设计

### 3.1 分工边界

| 环节 | AI / 系统承担 | 人工承担 |
| --- | --- | --- |
| 卖点提炼 | 从录入资料中拆分、归纳卖点 | 确认事实、产地、规格、资质是否属实 |
| 初稿生成 | 多平台文案、标签、分镜、配图提示词 | 选择与调整表达口吻、取舍内容 |
| 风险校验 | 分级扫描、命中定位、依据与润色建议 | 确认风险是否可接受、最终合规判断 |
| 受众评估 | 痛点 / 卖点覆盖与情绪倾向打分 | 结合实际受众反馈判断建议是否采纳 |
| 定稿发布 | 导出文件、留存日志与溯源 ID | 最终发布决策与对外口径负责 |

### 3.2 协作流程与留痕节点

```
AI 初稿生成
   │
   ├─ 系统合规扫描（内容侧 + 输入侧）→ 风险高亮、依据、建议
   ├─ 受众命中分析 → 覆盖率 / 情绪 / 补全建议
   │
   ▼
人工在线编辑（标题 / 正文 / 分平台文案 / 分镜 / 配图提示词）
   │
   ├─ 点击“保存人工修改并留痕”：与已提交基线做字符级 Diff
   ├─ 记录：时间戳、操作人、字段、动作、修改前后、增删字数
   ├─ 一键合规润色：系统替换稳妥表述，标记“待人工确认”
   ▼
定稿导出（MD / Word / 纯文本）+ 会话持久化 + 溯源 ID
```

### 3.3 版本与留痕实现

- **双版本留存**：`ai_content`（AI 原始初稿）与 `final_content`（当前工作稿）分别保存；
- **Diff 引擎**：基于 diff-match-patch 做字符级比对，输出保留 / 新增 / 删除操作序列与增删字数；
- **修改日志**：每条记录含时间戳、操作人、字段、动作类型、修改前后内容；
- **会话回溯**：历史会话列表展示项目、时间、合规结论、修改条数，可重新加载复核；
- **溯源标识**：溯源 ID 格式 `QL-YYYYMMDD-XXXXXX`，导出文件附带 AI 生成 + 人工校验说明与提示词版本号。

### 3.4 容错与异常处理

- 必填项缺失、卖点信息过短、未选平台：前端友好提示补全，不产生空输出；
- 在线模型异常：自动降级本地引擎并提示；
- 润色仅做稳妥化替换，最终措辞由人工确认；
- 所有输出可编辑、可导出、可回溯。

## 4. 业务价值说明

### 4.1 问题针对性

瞄准三类小团队“人手少、网感弱、多平台适配难、合规易踩线”的真实痛点；场景、用户、嵌入环节与适用边界在输入层与说明文档中均有明确界定。

### 4.2 可衡量价值

- 单条长图文初稿由约 120 分钟压缩至约 15 分钟（生成 + 微调），效率提升约 87%（基于人工流程对比的预期值，实际以团队实测为准）；
- 多平台内容一次生成、口径统一，减少重复改写；
- 合规风险前置暴露并附法规依据，降低事后返工与违规风险；
- 协作过程留痕，便于团队复盘、导师审阅与答辩举证。

### 4.3 数据与模拟素材说明

内置案例为演示用模拟素材；工具不编造历史典故、产地、工艺与资质。凡涉及数据、比例、检测报告、价格时效的表述，均提示“以官方发布 / 检测依据为准”；若后续接入真实业务数据，将在交付说明中补充数据来源与口径。

## 6. 工程化与部署说明

### 6.1 密钥安全

- 禁止将 API Key 硬编码进前端或公开仓库；
- 密钥仅经环境变量 / `.env` 注入，`.env` 已纳入 `.gitignore`；
- 界面配置概览仅展示脱敏状态。

### 6.2 部署方案

- **在线部署**：Streamlit Community Cloud / Hugging Face Spaces / Vercel / 腾讯云 CloudBase 均可；免费托管存在休眠机制，答辩前需提前访问唤醒。
- **本地 Plan B**：提供 `requirements.txt` 与 `run.sh`，可在本地 Python 环境离线运行；建议赛前准备完整工程包、安装包与演示录屏，应对现场无网络或服务宕机。

### 6.3 测试覆盖

- `tests/test_core.py`：输入校验、生成契约、合规识别、润色、受众分析、Diff、导出与持久化离线自测；
- `tests/test_app_smoke.py`：AppTest 模拟“加载案例 → 生成 → 留痕 → 导出”与空白输入容错链路。
