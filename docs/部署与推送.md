# 部署与 GitHub 推送说明

## 一、本地运行（Plan B，离线可用）

```bash
cd qilu-ai-communication-workbench
pip install -r requirements.txt
streamlit run app.py
```

未配置大模型 Key 时自动运行本地离线兜底引擎，全流程可完整跑通。

## 二、接入在线大模型（可选）

复制 `.env.example` 为 `.env` 并填写：

```bash
LLM_ENABLED=true
LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
LLM_MODEL=doubao-pro-32k
LLM_API_KEY=你的密钥
```

`.env` 已在 `.gitignore` 中排除，不会进入公开仓库。

## 三、推送到 GitHub

### 方式 A：已在本机配置好 git 凭据

```bash
cd qilu-ai-communication-workbench

# 若远端仓库尚未创建，先在 GitHub 网页新建空仓库：
# https://github.com/new
# 仓库名：qilu-ai-communication-workbench
# 不要勾选 “Add a README”、.gitignore 或 License

git remote add origin https://github.com/livai962/qilu-ai-communication-workbench.git
git branch -M main
git push -u origin main
```

### 方式 B：通过连接器推送（需写权限授权）

在 GitHub 连接器授权包含仓库写入（`repo`）权限后，可由工具完成：新建公开仓库 `qilu-ai-communication-workbench`，并将本地 main 分支全部文件一次性推送。

> 备注：本次环境的连接器授权为只读，建仓 / 推送接口返回授权失败；本地工程已完成首次 git 提交，恢复写权限后可直接推送，无需重新整理代码。

## 四、云端部署备选

- Streamlit Community Cloud：关联仓库后指定主程序 `app.py`；
- Hugging Face Spaces、Vercel、腾讯云 CloudBase 均可；
- 免费托管存在休眠机制，答辩前提前访问唤醒服务；
- 赛前保留本地工程包、安装包与三分钟演示录屏，作为无网络 / 服务宕机时的备用方案。
